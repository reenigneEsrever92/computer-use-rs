# Development

Every change to `desktop-use` — a feature, a bug fix, an improvement, or a
refactor — is first written down as a change request in the
[backlog](backlog/index.md). A change request states the problem, the proposal,
the decisions behind it, and its acceptance criteria; an implementation plan is
added before work starts. A change is done when its acceptance criteria hold and
the build and tests pass, at which point the [changelog](changelog.md) records
it.

## Start here

- [Backlog](backlog/index.md) — the change requests that define the work ahead,
  and what `kind` and `state` mean.
- [Changelog](changelog.md) — what has shipped, newest first.
- [Contributing](contributing.md) — how a change moves from proposal to done.

The requirements the backlog is derived from live in
[../requirements.md](../requirements.md).
